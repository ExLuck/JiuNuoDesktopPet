JiuNuo Desktop Pet · Feibi Jiubi feature test

How to use
1. Extract the portable package in full. For everyday use run "JiuNuoDesktopPet.exe" in the root folder; this entry point is only for demonstrating her exclusive actions.
2. If the pet is already running, exit it from the tray first.
3. Double-click "JiuNuoDesktopPet-FeatureTest.exe" inside the "Test Tools" folder.
4. Revision 6 runs in a fixed order: kick a window, punch it away, charge it, hide it in the hat, tease until the mischief bar fills, throw the hat to smash a window and store the shards, throw the hat to tear a window and store the halves, and recover the hat after a hatless interruption. The step identifiers in the report are Kick / Punch / Charge / HatStoreReturn / Tease / Shatter / Tear / HatlessInterruption. Window interactions only ever use the dedicated test window the program creates, and the real safety checks still apply. Filling the bar by teasing runs on its own and needs no window precheck.
5. Progress appears only in the right-click menu, the test window title and the report; no speech bubbles are shown. The hat-storing, smashing, tearing and hatless-interruption steps show "Right-click to restore" once the performance finishes. Right-click and choose "Give the window back", and confirm the real window has come back before continuing. There is no timeout on that wait and no required minimum; take as long as you like to confirm the window is not restoring on its own. While an animation is running, do not cover or move the test window, or the window action will be interrupted.
6. If a step fails, the run stops there and does not continue. Note the current step and its hint, fix whatever is in the way, then right-click and choose "Retry this item". Only once it passes does the next step run.
7. To stop early, right-click and choose "Stop feature test", click the pet, or exit the pet. Afterwards the dedicated test window is closed and the effects cleaned up, and your everyday settings and saved state are left untouched throughout.

Notes
- This entry point exists so you can watch the actions and hear the sounds yourself, and it shows both the pet and the test window. It is not an automated background test or a screen-recording tool.
- The test state is isolated from your everyday saved data. Autonomous mischief is deliberately off, no settings version upgrade is triggered, and you do not need to change any everyday setting to make the actions run. Normal mode has autonomy on by default; configurations from v4 or earlier get it enabled on first upgrade, and turning it off afterwards sticks.
- This entry point only demonstrates Feibi Jiubi's exclusive behaviour. It no longer separately demonstrates walking, running, sleeping, window physics, size, mute or going home, though mute, stop and the safety cleanup all still work.
- Normal mode likewise never restores a stored, smashed or torn window on a timer. Once the character finishes performing she goes back to normal activity. Only "Give the window back" in the right-click menu starts a restore; clicking the hat or the effects no longer triggers one.
- In normal mode, with something already in the hat, she can still kick, punch and charge another window. Right-clicking to return will stop the current small action first and retrieve what is stored; she will not take a second window or start a new hat-storing finisher. "Mischief" explains the toggle, build-up, cooldown, waiting and occupied states. Testing the autonomous rhythm, and two real windows at once, should be done by hand through the normal entry point; neither is part of these eight isolated demonstrations.
- If you right-click to restore during the eighth step, the simulated dragging and tossing stop immediately and returning the window takes priority. Not watching the hatless sequence through marks the step NeedsReview with Evidence.HatlessInterruptionObserved=false, which does not count as a full pass; you can run the entry point again to observe it properly.
- Quiet mode, going home, size changes and dragging across screens all preserve a held result. Switching characters, quitting, locking, sleeping, or a real change to the display layout or work area still return it safely. Choosing to stop during a test cleans up the program's own windows and is not recorded as a normal restore pass.
- Speech bubbles are disabled for both Nuonuo and Feibi Jiubi here. Voice, the hunger and mischief bars, and the right-click and tray menus all remain.
- Your existing size, volume and mute preferences are inherited; if you already had sound muted, it is not switched back on for you. You can mute from the right-click menu during the test.
- While testing, watch how the actions join up, where the windows end up, and the mischief bar and the voice. If something looks wrong, note roughly when it happened and which action was running, so it can be matched against the trace log.
- After a finisher completes its destruction, the shards or the two halves should end up in the hat with the real window still minimized. They should only come back after you right-click to restore; shards should never be left scattered on the desktop permanently, and the window should never restore by itself.
- An attack should show a wind-up, a fast strike, a brief hit pause with a small flash of stars, the window moving quickly away, and a single rebound. There is no added crouch, reach or gloating. A finisher is slowed down so the wind-up and the destruction are visible; she calls out "Feibi Jiubi" first and only approaches the window and throws the hat once the line finishes, or continues straight into the action if sound is muted.
- If a pet or a test is already running, this entry point tells you to exit it first and does not hand the launch request to the existing instance.
- Keep "Test Tools" and "Program" inside the same portable directory, and do not move this EXE on its own.
- For everyday use, double-click the single normal entry point "JiuNuoDesktopPet.exe" in the root of the portable directory, which never runs the test automatically; this test entry point stays in its subfolder.
- The step-by-step report is saved to %TEMP%\SoftMochiPet.FeatureTest\<this session's folder>\feature-test-report.json, and FeatureDemoStarted / FeatureDemoFinished in the log record which folder was used.
- The report should say Revision 6. WaitingForManualRestore means a normal wait, not a failure; ManualRestoreRequested means a real right-click request was accepted. ManualRestore.HeldSeconds records how long it actually waited and RequestedAt records when the request came in. Restoring quickly is perfectly valid, but it does not mean a long hold was properly observed.
- Completed requires the window action's real movement, or the minimize and return check, to have passed, and every holding step must go through a real right-click request and a confirmed restore, including the hatless-interruption step. It does not mean the whole run, its visuals and its sound have been signed off by a person. Multiple monitors and scaling, real mouse operation in normal mode, starting with Windows, and locking the screen all still need checking by hand; this demonstration never changes the start-with-Windows setting.
